--- Before Day-4 ---
I already knew the basics of how websites and APIs communicate over the internet. I had heard of HTTP requests such as GET and POST and had used APIs in Python projects, but I was not very familiar with HTTP status codes, browser network debugging tools, or creating APIs from scratch.

## Day-4 Checklist

* [x] I know the 5 core HTTP methods (GET, POST, PUT, PATCH, DELETE) and what each is used for
* [x] I can read a status code and know what went wrong — e.g., 401 vs. 403 vs. 404 vs. 500
* [x] I can open Chrome DevTools Network tab, find a request, and inspect its headers, payload, and response
* [x] I can copy a browser request as a cURL command and run it in the terminal
* [x] I can change the `User-Agent` in the browser and see the change in the Network tab
* [x] I can use `curl` to make a GET request with query parameters and a POST request with a JSON body
* [x] I have a running FastAPI app with at least two endpoints (`GET /health` and `POST /echo`)
* [x] I can test my API using the Swagger UI at `/docs` and via `curl` from the terminal

--- After Day-4 ---
I learned how HTTP requests and responses work in practice and how different HTTP methods are used in real applications. I became more comfortable reading status codes and debugging API issues. Using Chrome DevTools helped me understand what information is exchanged between a browser and a server. I also learned how to replicate browser requests using cURL and how to build and test simple APIs with FastAPI. Exploring the Swagger UI made API testing much easier and showed how API documentation can be generated automatically.
