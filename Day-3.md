--- Before Day-3 ---  
I already knew how to write and run basic Python programs. I had used `pip` to install packages and was familiar with Jupyter notebooks for data science tasks. I had also used VS Code for coding but was not very familiar with Python project management tools like `uv`.  
----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------  

## Day-3 Checklist  

* [x] I can run a Python script using `uv run script.py` without setting up a local virtual environment
* [x] I know where the temporary virtual environment is created when running the `uv add --script script.py pandas` command followed by `uv run script.py`
* [x] I can create a new Python project using `uv init` and understand what `pyproject.toml` is used for
* [x] I can add a dependency (e.g., `requests`) using `uv add` and see it reflected in the lockfile
* [x] I can create a traditional virtual environment using `uv venv` and know when to use it
* [x] I understand why installing packages globally with `pip install` is a bad habit
* [x] I can open a project in VS Code, select the correct Python interpreter, and run code from the integrated terminal
* [x] I know the difference between a `.py` script and a `.ipynb` notebook, and when to use each

--- After Day-3 ---  
I learned how `uv` simplifies Python dependency and environment management. I understood the purpose of `pyproject.toml` and lockfiles in maintaining reproducible projects. I learned different ways to manage dependencies, including temporary script-based environments and dedicated virtual environments. I also gained a better understanding of how VS Code interacts with Python interpreters and environments. Additionally, I learned when to choose a Python script versus a Jupyter notebook depending on the task.
